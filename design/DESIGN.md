# DESIGN — 门锁观察簿

> 这是已交付界面的样式与组件契约。后续每次可见界面修改都先完整读取本文件；如需新增变体或改变系统方向，先修改契约，再改页面。

## Identity

- **感受：** 像一本可核对、可盖章、可撤销的门口观察簿。
- **Moment of care：** 事件详情把原录像、最佳人脸、模型决定、人工修正与处理进度组成可解释证据带。
- **Register：** system；这是多屏管理工具，没有营销式视觉高潮，屏间一致性优先。

- 页面正文 `16px / 1.55`；标题使用 `clamp(28px, 3vw, 42px) / 1.06`。
- 主间距由 `8 / 12 / 14 / 16 / 18 / 20 / 24 / 28 / 32 / 38 / 52px` 组成；不得为单个页面另造近似值。
- 层级：主导航 `30`、Toast `60`、跳转链接 `100`；弹窗使用原生 `dialog` 顶层。
- 阴影只用于工作区、登录纸张、弹窗和 Toast；普通记录行与人物项使用细线分隔，不堆叠卡片。

## Typography

- **Display：** `Noto Sans SC`、`Microsoft YaHei UI`、`PingFang SC` 回退；页面标题 700–800 字重、紧凑负字距。
- **Text：** 同一无衬线家族；正文 16px，小型辅助信息 12–13px，行长由内容网格限制。
- **Numerals：** 时间、计数与表格数据启用 `tabular-nums`；不引入等宽字体制造技术感。
- 新增文字必须复用现有字号与字重层级，不增加字体文件或装饰性衬线。

## Color rules

- Commitment tier：restrained；冷白纸张占绝大多数表面，蓝色只标记导航、主操作与选择。
- 绿色只表示正常/已确认，琥珀只表示待处理，朱红只表示人工盖章、危险或失败；每个状态同时包含文字或形状，不能只靠颜色。
- 朱红不能用作装饰，蓝色不能代替错误语义。
- 禁止渐变、近黑监控墙、霓虹绿、大面积暖米白和装饰性玻璃效果。

## Motion vocabulary

1. 控件背景、边框、文字与透明度：`140ms ease-out`。
2. 开关状态：`180ms ease-out`。
3. 跳转链接进入：`150ms ease-out`；加载圆环仅在用户未请求减少动态时持续旋转。

- hover 仅在 `@media (hover:hover) and (pointer:fine)` 下启用。
- active 通过 `opacity: .72` 表达按下；focus-visible 使用 3px 半透明蓝色轮廓与 2px 偏移。
- `prefers-reduced-motion: reduce` 下移除过渡并停止加载旋转；不得新增第四种动效家族。

## Layout patterns

- 桌面壳：216px 左侧导航 + 流体主区；中尺寸缩为 76px 图标轨；680px 以下改为底部四项导航。
- 事件页使用 5/7 非对称账页分栏；1050px 以下变为事件列表在上、证据详情在下。
- 页面开场只允许“自然语言标题 + 一句任务说明 + 可选右侧操作”，不使用 eyebrow、kicker 或营销口号。
- 组件库存：按钮 `primary / quiet / danger / icon`；输入 `password / search`；选择器 `standard`；链接 `navigation / inline`；表格 `dense ledger`；开关 `standard`。
- 非控件模式：状态标记、人物项、证据项、通知、原位加载、空状态和审计时间线。新增页面先组合这些模式。
- 控件最小触控目标 44×44px；移动端不得出现水平页面滚动。

## State recipes

- **Selected/current：** 蓝色软底 + 3/4px 蓝色内侧标记，并保留文字语义。
- **Loading：** 在内容原位保留布局，不使用整页遮罩。
- **Empty：** 说明为什么为空，并提供唯一恢复动作。
- **Error：** 错误出现在失败对象附近，以自然中文描述原因和恢复动作。
- **Disabled：** 不只降低透明度；必须保留可读文字，原因不明显时紧邻说明。
- **Focus：** 所有按钮、链接、输入和选择器保留统一可见轮廓。

## Copy voice

- 克制、明确、可恢复。
- 代表标题：“门口发生了什么”。
- 按钮使用动词开头，如“确认并命名”“标记为误检”“重新分析”；不使用“提交”“执行操作”等技术或空泛词。
- 面向用户不出现模型、容器、队列、主键等内部术语；技术细节只进入诊断或运维文档。

## Project ban additions

- 不为真实录像、人脸或身份设计公开演示 fixture；浏览器验收只用隔离容器和合成数据。
- 不显示设备编号、私有路径、域名、凭据或精确家庭时间线。
- 不使用 KPI 卡片拼盘、监控墙、彩色状态栏或无解释的置信度排行。
- 当前没有 `auteur-allow` 抑制项；新增抑制必须在本节记录规则和理由。

## Rejected — decisions that already have a history

| 曾尝试/常见答案 | 为什么不采用 | 当前方案 |
|---|---|---|
| 近黑背景、霓虹绿色在线点 | 像通用安防监控墙，日常查看疲劳且把状态当装饰 | 冷白记录纸、蓝黑墨与文字化健康状态 |
| 暖米白、衬线标题和松散卡片 | 从监控墙摆向生活方式杂志，降低扫描效率 | 高密度账页、无衬线层级与细线分隔 |
| KPI 卡片阵列 | 把少量家庭事件包装成经营指标，割裂证据链 | 单条汇总带 + 事件账页 + 证据详情 |
| Unicode 文字符号充当导航图标 | 字体和平台渲染不稳定，语义尺寸难统一 | 同一描边规则的内联 SVG 图标 |
| 全局把动画压到极短时长 | 破坏原位反馈，也没有真正尊重减少动态偏好 | 针对性 `prefers-reduced-motion` 规则 |
| 生产页面接受 `?fixture=` | 会把测试入口带进生产攻击面并造成状态歧义 | 隔离测试容器、合成数据库和测试标签故障注入 |

## Editing protocol

1. 修改界面前完整阅读本文件与 `SYSTEM-SHEET.md`。
2. 新视图复用现有页面开场、组件库存、状态配方和三种动效家族。
3. 若确实需要新变体，先更新本文件与变体预算，再实现代码。
4. 每次可见修改后运行 Auteur `slopscan` 与 Impeccable 检查，并重新截图受影响的 390 / 768 / 1440 视口。
5. 对照相邻页面检查家族一致性；“修复”上表已拒绝方案视为回归，除非先改契约并记录理由。
