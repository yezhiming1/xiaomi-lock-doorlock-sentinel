# 小米门锁录像识别训练

本项目把已经下载到 NAS 的小米门锁事件录像，转成可人工复核、可持续学习的人物记录。系统不会读取 Home Assistant、米家或小米云凭据，也不会参与开锁。

当前交付版本为 `V0.0.1`，正式应用位于 [`doorlock-sentinel/`](doorlock-sentinel/)。仓库根目录只保留产品边界、项目状态与设计资料；运行数据、模型、录像、脸图、向量、密码和私有地址均不进入 Git。

`V0.0.1` 已部署到目标 NAS，生产容器、真实模型、只读输入、持久化数据库和公网密码入口
均通过分层验收。当前私有录像批次已全部处理且分析错误为 0；不清晰或没有可用人脸的
录像按固定原因跳过，不视为系统失败。训练仍会永久持续，现阶段不宣称真实人物准确率，
身份与风险通知继续关闭。

## 已冻结方案

- 运行位置：NAS 单机运行，电脑不参与日常处理。
- 输入：现有小米门锁云录像下载器写入的只读录像目录。
- 人脸方案：SCRFD 2.5G 检测、ArcFace R50 特征、ONNX Runtime CPU。
- 资源策略：单录像串行推理，ONNX Runtime `2/1` 线程，适配 Intel N100。
- 学习方式：不预先录入人脸，只从自然事件录像中形成未知人物簇；由管理页面人工命名、合并、拆分或撤销。
- 多人同框：逐人跟踪；同一画面中的人物建立永久不可合并约束，防止身份污染。
- 样本保留：高质量、具有差异性的代表样本永久保存且不限制数量；低质量和重复样本不进入原型库。
- 通知：训练期关闭身份和风险通知，运行故障通知保持开启；企业微信真实账号配置后才能完成通知验收。
- 录像保留：普通本地数据保留 35 天；115 备份、月度封存、校验和备份后删除由独立专项任务负责。
- 管理入口：密码登录，无用户名；支持事件、人物、证据、失败重试、备份回执、运行状态和审计记录。
- 公网入口：复用 NAS 的共享入口网关，不为本项目新建独立隧道。

## 数据流

```text
小米门锁云录像下载器
  ├─ 原子写入录像与下载状态日志
  ▼
Doorlock Sentinel（单容器）
  ├─ Python：摄取、推理、人物学习、数据库、管理页面、Outbox
  └─ Node：企业微信官方智能机器人 WebSocket
  ▼
115 备份专项任务
  ├─ 读取导出清单
  ├─ 上传、校验、月度封存
  └─ 回写可审计备份回执后执行保留策略
```

## 交付边界

仓库代码可以独立构建和测试，但以下验证必须严格区分：

- 本地与容器自动测试：由本项目完成并记录。
- NAS 部署与真实录像处理：只在目标 NAS 上验证。
- 企业微信真实消息：在 Bot ID、Secret 和目标 UserID 由用户私下配置前为 `UNKNOWN`。
- 115 真实上传和备份后删除：由 115 备份专项任务验收，本仓库只提供清单和回执接口。
- 实际门锁人物识别准确率：需要持续人工标记后的真实样本才能逐步形成，首版不能预先宣称准确率。

详细架构、部署与运维文档见 [`doorlock-sentinel/docs/`](doorlock-sentinel/docs/)，项目状态记录见 [`docs/`](docs/)。
