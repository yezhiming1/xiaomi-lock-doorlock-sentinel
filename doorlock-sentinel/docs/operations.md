# 运维与故障处理

## 日常检查

管理页面的“系统”页统一显示：

- 数据库和模型健康。
- 已摄取事件、人物和未知簇数量。
- 分析失败及下次重试时间。
- 下载器状态和固定错误码。
- 待备份、已验证、失败或缺失的制品数量。
- 最近审计与可撤销人工操作。

容器层同时检查 `/health/live`、`/health/ready` 和 Docker 健康状态。`ready` 为 200 才表示数据库与模型都可用。

## 分析失败

一次分析失败按 `5/20/60` 分钟自动重试。超过自动重试计划后进入 `dead`，写入 `system.analysis_failed` Outbox。管理页面可请求重新分析，操作有审计记录；不得直接改数据库绕过状态机。

如果文件不清晰但视频本身有效，不视为系统失败。系统保存 `no_face_detected`、`face_too_small`、`blur_too_low` 等固定跳过原因并继续处理下一条录像。

## 下载失败

下载器 `V0.0.4` 把固定状态写入只读 JSONL 日志。前两次连续基础设施失败显示 `retrying`，第三次仍失败显示 `failed` 并进入运行故障 Outbox；成功后状态恢复为 `downloaded`。

状态文件非法只报告 `DOWNLOAD_STATUS_INVALID`，不记录或通知原始行。若录像共享存储整体不可写/不可达，状态日志也可能无法更新，需要同时依赖 Home Assistant 固定错误日志和 NAS 存储监控。

## 企业微信故障

Outbox 领取后只有真正发送成功才确认。发送失败使用租约和退避重试，不丢弃原消息。启用企微后，Bot WebSocket 心跳持续失败会使容器健康降级；禁用企微时不影响录像处理。

真实 Bot ID、Secret 和 UserID 尚未配置时，企微生产发送验收必须标为 `UNKNOWN`，不能用 stdout 测试替代。

## 备份与保留

Doorlock Sentinel 周期性导出 `runtime/exports/artifact-manifest.json`。这是私有运行制品，包含本地路径，只能由 115 备份专项任务通过受保护的内部接口或私有挂载读取，不得上传到 Git。

备份任务必须：

1. 按清单上传录像、普通派生证据、永久人物样本、模型和数据库快照。
2. 读取远端大小和 SHA-256。
3. 回写 `verified`、`failed` 或 `missing` 回执。
4. 只有 `verified` 且达到保留期时才执行普通本地文件删除。
5. 永不删除永久身份、模型、数据库快照和高质量代表样本。

本项目不直接登录 115，不执行月度封存，也不宣称外部上传成功。

## 数据库快照

内部快照接口使用 SQLite 在线 backup API，然后在目标快照执行 `PRAGMA integrity_check`。成功快照登记为永久制品并进入备份清单。复制正在写入的单个 SQLite 主文件不能替代此步骤。

## 模型问题

启动时核对两个模型 SHA-256、输入输出约定和 512 维特征。任何不一致使 readiness 降级，不会带着错误权重继续学习。升级模型时保留旧版本与数据，重新嵌入后旁路比较。

## 日志与取证

日志只允许固定错误码、组件名和请求 ID，不得包含异常堆栈、密码、令牌、UserID、原始 SDK 消息、云端 URL、录像名、私有路径、向量或人脸。发生故障时先保存容器日志、镜像摘要、数据库快照和清单，再执行回滚。

## 不支持的操作

V0.0.3 管理页面没有手动删除录像、人物或样本功能。删除属于备份验证后的保留流程，避免一次误操作破坏训练和审计数据。
