# 架构与数据所有权

## 单容器、双进程

`recognition` 和 `wecom-bot` 由 Supervisor 分别监控。二者共享一个容器发布单元，但不是一个进程，也不共享数据库写权限。

### recognition（Python）的职责

- 只读扫描下载器输出目录。
- 验证普通文件、路径边界、写入稳定性、视频可读性和内容摘要。
- 串行执行 SCRFD 检测与 ArcFace 特征提取。
- 形成轨迹、同框约束、身份匹配和未知人物簇。
- 处理人工命名、改名、合并、拆分、误检与撤销。
- 作为 SQLite 唯一写者，维护 Outbox、审计、制品清单和备份回执。
- 提供管理页面、健康端点和仅回环可用的内部 API。

### wecom-bot（Node）的职责

- 使用企业微信官方智能机器人 SDK 建立 WebSocket。
- 通过 `127.0.0.1` 内部 API 领取 Outbox。
- 只向一个明确配置的 UserID 发送固定字段通知。
- 成功后确认，失败后以固定错误码延迟重试。
- 不连接 SQLite，不读取录像、人脸、向量、管理密码或备份清单。

## 主数据流

```text
下载器输出目录（只读挂载）
  ├─ xiaomi_lock_*.mp4
  └─ .xiaomi_lock_backup_status.jsonl
             │
             ▼
IngestWorker ── SHA-256 / 租约 / 重试 / 去重
             │
             ▼
ProcessingPipeline
  ├─ Metadata → downloader time
  ├─ SCRFD → 人脸框、五点关键点、质量
  ├─ ArcFace → 512 维归一化特征
  ├─ Tracking → 每人每录像一条轨迹
  ├─ CannotLink → 同帧人物永久冲突
  ├─ IdentityMatcher / UnknownClusterer
  └─ ArtifactManifest / Outbox
             │
             ▼
SQLite WAL（Python 单写者）
  ├─ 管理页面人工复核
  ├─ 企业微信故障通知
  └─ 115 专项任务清单与校验回执
```

## 模块划分

模块按变化原因和故障边界拆分，而不是按每个函数创建文件：

- `ingest.py`：输入发现、租约和重试状态机。
- `pipeline.py`：一次录像处理的事务编排。
- `face_backend.py`：模型校验、推理、对齐和质量门槛。
- `tracking.py`：时空与特征联合跟踪，同帧关系计算。
- `recognition.py`：匹配、聚类、原型准入和紧凑检索索引。
- `people.py`：人工数据修正和可撤销操作。
- `artifacts.py`：本地制品、保留类别、清单和备份回执。
- `security.py`：密码、会话、持久限速、CSRF 和审计。
- `web_*.py`：面向管理页面的读写接口。
- `internal_api.py`：只给同容器 bot 和备份任务使用的令牌接口。

## 多人物与自然学习

每个采样帧先检测全部人脸，再使用外观相似度、位置、IoU 和时间间隔形成独立轨迹。轨迹保存全部出现过的帧索引，但只保留少量高质量代表帧用于计算，从而兼顾同框正确性和内存占用。

同一帧出现的两条轨迹写入永久 `cannot_links`。无论自动聚类、人工合并人物还是人工合并未知簇，都必须先检查这一约束。连续片段如果从未同框，可以根据后续证据或人工操作重新合并。

所有人物原型永久保存且不限制总数。为控制 N100 推理后的匹配成本，检索索引只启用质量最高且外观多样的一组原型，同时以全部原型更新人物质心；这不会删除历史样本。

## 一致性与恢复

- 视频事件、轨迹、跳过原因、同框约束、人物观察和通知在数据库事务中提交。
- 处理中断后由租约恢复；同内容摘要和唯一约束避免重复事件。
- 分析产生的图片只有在事务未提交时才清理；事务已提交而清单导出失败时，由后台清单协调器补齐。
- Outbox 使用租约、确认、拒绝、重试和去重键，bot 重启不会丢消息。
- 备份回执只有远端大小和 SHA-256 都与本地清单一致时才能标记 `verified`。
- 管理操作包含幂等键、前后状态和撤销记录。

## 资源边界

V0.0.3 只允许一个录像推理任务。默认每秒抽取 2 帧、每段最多 120 帧，ONNX Runtime 使用 `2` 个 intra-op 和 `1` 个 inter-op 线程。Node bot 与清单协调器是轻量 I/O 任务，不增加第二条推理流水线。

## 明确外部边界

- 小米云访问归下载器所有；本服务不读取其登录态。
- 115 上传、月度封存、恢复演练和备份后删除归备份专项任务所有。
- 公网 TLS 与路由归共享入口网关所有；应用只绑定 NAS 回环端口。
- 人工复核结果只改变识别数据，不触发门锁控制。
